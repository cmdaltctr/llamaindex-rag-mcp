## Why

ADR-029 documents a 5-week production incident where the reranker silently failed on every call — the fallback logged a WARNING to stderr, which MCP clients capture but do not surface to the user, and returned un-reranked results with no escalation. ADR-029 decision #3 explicitly deferred the fix ("Non-silent fallback (refactor reminder)") to a later refactor that never happened. An audit of the codebase for the same failure shape (catch → warn → silently substitute a default, with no escalation and no test) found three more untested instances at the composition root and in provider selection. Each one risks the same class of incident: a real misconfiguration or construction failure that produces a working-looking system running on the wrong thing.

## What Changes

- **BREAKING**: `config/__init__.py::_validate_provider_selections` SHALL raise `ValueError` instead of warn-and-clamp for unrecognised `EMBED_PROVIDER`, `METADATA_LLM_PROVIDER`, `LOCAL_BACKEND`, `CLOUD_BACKEND`, `RETRIEVAL__HYBRID_SPARSE_BACKEND`, and unrecognised `DOCUMENT_BACKEND` values — matching the existing `VECTOR_STORE` precedent (ADR-034), which already fails loudly at compose time. This does **not** touch the two deliberate graceful-degradation policies already in the codebase: `DOCUMENT_BACKEND=azure` with missing credentials still falls back to local (required by the cloud-opt-in hard boundary), and unknown `RAG_PROFILE` still falls back to `documents` (required by the profile system's own degrade-gracefully design). `PDF_READER`'s unknown-value handling is untouched — it has its own separately specified capability (`pdf-reader`) and touching it here would entangle this change with unrelated spec drift already flagged elsewhere.
- **BREAKING**: `compose.py::ensure_runtime_setup` SHALL raise instead of warn-and-continue when `build_embed_model` or `build_vector_store` fails. The embed-model guard masks reachable failures today: `build_embed_model` raises `ValueError` for missing OpenRouter credentials and `ImportError` for missing optional deps, and the process still reports successful startup with no embed model set. The vector-store guard catches close to nothing at present (Chroma's client is created lazily, so construction rarely fails), so removing it is about not leaving a guard that would mask *future* construction errors — a green startup does not prove the store is usable either way. Because `ensure_runtime_setup()` is invoked at `compose.py` module scope, both failures surface at import; that is accepted and consistent with the existing `VECTOR_STORE` check (see design.md).
- The reranker (`core/retrieval/reranker.py::rerank`) SHALL distinguish a transient failure from a persistent one. After N consecutive failures with the same error signature, the log level escalates from WARNING to ERROR. Retrieval SHALL still return un-reranked results — the reranker never aborts a search — but the persistent-failure state SHALL be visible in `rerank_reason` when `include_diagnostics=True`, per the existing diagnostics mechanism in `core/retrieval/pipeline.py::search`.
- The `RERANK_ONNX_PROVIDER=coreml` selection guard (currently real but unspecified behaviour from ADR-029) gains an explicit spec and test coverage: default CPU, opt-in CoreML when available, silent-to-CPU when CoreML is requested but unavailable (already correct; needs to stop being untested).
- The ÷30 similarity-threshold scaling SHALL follow the rerank *outcome* rather than the rerank *request*. Today `_effective_threshold` scales on intent, so when the reranker fails the threshold is divided by 30 while the scores remain un-reranked cosine similarities — filtering becomes ~30× too permissive and noise reaches the caller. This was live on every reranked search throughout the 5-week outage. The calibrated factor itself is unchanged.

### Modified Capabilities
- `reranking`: the "reranker as singleton with recovery" requirement gains consecutive-failure escalation; the "reranked provenance flag" requirement gains failure-reason surfacing in diagnostics; a new "ONNX execution provider selection" requirement documents the existing CoreML/CPU guard.
- `config-composition-root`: gains a requirement that composition-root construction failures (embed model, vector store) fail startup rather than continuing in a partially-built state.
- `inference-backend`: the "Unknown provider value" scenario changes from warn-and-clamp to raise-and-fail-startup, and the "Split embedding and metadata LLM provider selection" requirement does the same for `METADATA_LLM_PROVIDER`. Both requirements also have stale prose corrected: the accepted `EMBED_PROVIDER` set is `local`/`cloud`/`ollama`/`llamacpp`/`openrouter` with default `local` (the spec previously said `ollama`/`llamacpp`/`openrouter` with default `ollama`, which no longer matches the code or `.env.example`). Correcting this is not optional housekeeping — leaving it would make "raise on anything outside the set" mandate that the shipped default config fail startup.
- `score-normalisation`: gains a requirement that the ÷30 threshold scaling is applied on rerank success, not on rerank request.

## Impact

- **Code**: `src/rag_mcp/config/__init__.py` (`_validate_provider_selections`), `src/rag_mcp/compose.py` (`ensure_runtime_setup`), `src/rag_mcp/core/retrieval/reranker.py` (`rerank`, consecutive-failure tracking), `src/rag_mcp/core/retrieval/pipeline.py` (`search`, diagnostics surfacing).
- **Tests**: new tests for every previously-untested clamp/fallback branch; coverage floor ≥95% (`core/retrieval`, `config/` are in the top tier).
- **Docs**: `docs/adr/029-...md` gets a "Resolved by" follow-up note; `docs/guides/reranker.md` and `docs/guides/configuration.md` document the new fail-loud behaviour and the escalation threshold.
- **Breaking**: any deployment currently running with an invalid `EMBED_PROVIDER`/`METADATA_LLM_PROVIDER`/`LOCAL_BACKEND`/`CLOUD_BACKEND`/`RETRIEVAL__HYBRID_SPARSE_BACKEND`/`DOCUMENT_BACKEND` value (a pre-existing misconfiguration masked by the current clamp) will now fail to start instead of silently running on the fallback. Targets `v3`, the breaking-change branch.
- **Explicitly out of scope** (recorded in design.md non-goals): the broad `except Exception` blocks in `core/documents/similarity.py`, `core/metadata/*`, `daemon/watcher.py`, `core/vectordb/chroma.py`, and `core/ingestion/writer.py`; `core/profiles/contract.py`'s safety-contract exception-swallowing; the ÷30 rerank-threshold scaling and `DOC_SIMILARITY_THRESHOLD` calibration constants.
