## Context

Three independent failure classes were isolated on 2026-09-09 by running
the 14 failing tests once with the ADR-063 promotion changes stashed:
13 reproduced without them. Each class has a distinct mechanism, so the
repair work is ordered cheapest-and-most-mechanical first, with a full
fast-suite run as the acceptance gate. The suite must be green on both
a machine with a populated operator `.env` and a clean CI runner, or the
fix is incomplete.

**In plain terms:** the automated test run is red for reasons that have
nothing to do with the code under test. One group of tests calls helper
functions that changed shape. A second group accidentally reads the
developer's private settings file. A third group counts files that were
added since the count was written. Fix all three, and the test run goes
green again.

## Goals / Non-Goals

**Goals:**

- Fast suite (`uv run pytest -m "not slow"`) passes with zero failures
  on a developer machine carrying a real `.env` and on a clean CI
  runner.
- Every fix asserts the same behaviour the corresponding test asserted
  before its breakage; no test is weakened, skipped, or deleted to get
  green.
- The stash-and-rerun evidence trail (which failures belong to which
  cause) is preserved in the change record.

**Non-Goals:**

- No production behaviour changes. If a cause turns out to be a real
  production defect rather than test drift (for example, if
  `query_instruction` was never meant to reach `_dense_query_rows` on
  some path), stop and surface it instead of patching the test around
  it.
- No reformatting, renaming, or "improving" of adjacent test code
  (surgical-change rule).
- No coverage-threshold recalibration; the floors stand as they are.

## Decisions

### D1. Reranker fakes accept the full production call signature

`_dense_query_rows` now receives `query_instruction=`. The test fakes
in `test_retrieval.py` get matching keyword parameters. Alternative
considered: `**kwargs` catch-alls in the fakes. Rejected as a default:
an explicit signature keeps the fakes honest when the production call
grows again, and the failure mode (explicit `TypeError`) is the signal
this drift previously lacked. Where a fake legitimately ignores the
value, the parameter is named and discarded with a comment.

### D2. Ambient-dotenv isolation for fresh-Settings tests

Tests asserting packaged-default resolution construct
`Settings(_env_file=None, ...)` — the pattern already proven in
`tests/test_embedding_tokenizer_settings.py`. Alternative considered:
deleting or renaming the developer's `.env` around the suite. Rejected:
mutating the operator's environment from a test harness is the exact
blast-radius failure the working-directory guard exists to prevent.
If a test genuinely needs dotenv-file behaviour, it creates its own
temp file and passes it explicitly.

### D3. Inventory marker recounts from disk, once, by hand

The integration inventory marker and its documented table are updated
to the real 18-module layout, with the module list generated by the
same discovery command the test uses (so the diff is reviewable). The
count stays a hand-maintained pin on purpose: the test's value is that
adding `omrg.integrations.*` modules remains a visible, deliberate act.
Alternative considered: deriving the count dynamically inside the test.
Rejected: that converts a drift detector into a tautology.

### D4. The cascade test is verified, not edited

`test_clean_base_tripwire` re-runs the base suite as a subprocess. It is
re-run after causes 1–3 are fixed and expected to pass unchanged. Any
edit to it is out of scope unless it still fails with all three causes
repaired, which would indicate a fourth cause to investigate separately.

## Risks / Trade-offs

- [A fake accepts the new kwarg but production semantics for it were
  themselves wrong] → The repair only restores the pre-drift assertion
  target; if the assertion then fails on values (not signatures), that
  is a real defect and blocks the change.
- [`_env_file=None` hides a genuine dotenv-loading requirement in
  `compose`] → Scoped to tests that assert packaged defaults; any test
  of dotenv loading itself keeps an explicit file.
- [Marker recount goes stale again] → Accepted; the test failing loudly
  is the designed behaviour, and the recount is a two-line fix next
  time.

## Migration Plan

Single branch, no deployment. Rollback is `git revert` of the repair
commit(s). Worktree: created fresh for this change per the sibling
worktree pattern; nothing runs against the main checkout.

## Open Questions

None material. The exact kwarg shape for the reranker fakes is decided
by reading the single production call site at implementation time.
