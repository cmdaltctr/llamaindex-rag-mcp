# Proposal

## Why

OMRS can say where a chunk came from (ADR-052 lineage) and whether a chunk is relevant (dense + sparse + RRF + optional reranker), but it cannot say whether a chunk is still *controlling*. When a corpus holds an original policy, an addendum that narrows it, and a later document that replaces part of it, all three are legitimate, all three stay indexed, and all three can score highly. The current pipeline hands the reranker a set in which an obsolete rule and its replacement are indistinguishable, and the calling agent is left to guess. This is the failure the fellowship paper targets: retrieval that separates *relevance* from *authority*, using a resolution ordering drawn from the uṣūl al-fiqh treatment of apparently conflicting evidences (reconcile before you supersede; the specific qualifies the general; the restricted qualifies the unrestricted; supersession needs evidence; withhold judgement when nothing resolves the conflict).

Why now: the lineage work is done, the answer pipeline already has an evidence-and-verdict shape (ADR-057, ADR-059), the retrieval registry and the ADR-080 operation catalogue make a new stage a small addition, and the competing literature (EvoTrustRAG 2608.07933, ConflictRAG 2605.17301, ArbGraph 2604.18362, SAT-Graph RAG 2505.00039 / 2510.06002) collapses every conflict into "which claim wins" or needs a hand-built ontology. A typed, evidence-bearing, deterministic-first relation layer is the open gap, and the sixteen-week fellowship window (October 2026 to the end of January 2027) fits a build, an experiment, and a paper.

## What Changes

- **New `core/authority/` package** (settings, relation vocabulary and edge model, sidecar storage, deterministic extraction, post-ingest linking, query-time resolver, model-tier pair proposer). It never imports `core/ingestion/`, `core/retrieval/` or `core/answer/`; it reads stored rows through the `core/vectordb` store contract and plain metadata key strings. It may import `core/documents/` for the model-tier pair proposer only. Retrieval reaches it only through the registry string.
- **New settings block `AuthorityBlock`** on `EffectiveSettings` with `enabled: bool = False`. Env prefix `AUTHORITY__`, also settable in `omrs.jsonc` (ADR-087). Profile-overlaid: the `documents` profile may enable it, `codebase` keeps it off.
- **Two opt-in routes, base pipeline unchanged when off.** Built-in profiles: the `authority.enabled` switch runs the resolver inside `search()`. User profiles (ADR-080 graphs): a new `authority.resolve` graph operation, registered with the retrieval graph adapters, that a Search graph can include. When the switch is off or the graph has no such step, every search surface returns exactly what it returns today.
- **Relation sidecar per collection.** Directed, typed, evidence-bearing edges between sources: `corroborates`, `explains`, `specialises`, `restricts`, `amends`, `supersedes`, `conflicts_with`. Each edge stores scope, effective dates, the evidence chunk id and text, `relation_origin ∈ {explicit_text, model}`, and confidence. The sidecar lives on local disk beside the store (`<store root>/_authority/<collection>/`). Chroma Cloud (ADR-045) and non-local LanceDB URIs are not supported: the step is skipped and `omrs authority rebuild` refuses with a clear message.
- **Linking runs after ingestion, never inside it.** A post-ingest pass, called from `Engine.ingest` and from `omrs authority rebuild`, extracts relations from new or changed sources and re-resolves references that were pending. Ingestion order does not matter. `core/ingestion/` is not changed.
- **Deterministic extraction tier (default when enabled).** Rule-based detection of supersession, amendment, repeal, effective-date and clause-reference language. Emits edges with `relation_origin=explicit_text`.
- **Optional model tier (opt-in, off by default).** A local decision model types candidate pairs. Which model is decided later (task 9.1): Experiment 38 found Julia 1 weaker than Clef-flash, and an NLI cross-encoder is a third option. It types candidate pairs from document-graph similarity edges plus shared clause references, capped per source. Emits `relation_origin=model` with a probability. Model-typed edges never enter `core/documents/doc_graph.py` (invariant 8 stays intact).
- **Resolver output contract.** Each candidate row gains `authority_status ∈ {controlling, qualified, superseded, historical, not_yet_in_force, unresolved_conflict, unknown}`, `authority_reason` (the edge that set the status, plus `qualified_by`) and `authority_conflicts` (the conflicting rows and the reason). `search()` still returns `list[dict]`. Rows are never dropped, and scores and order do not change. Later stages keep the annotations: the rerank-failure fallback re-applies them, a cut partner stays referenced, and assembly never merges rows with different annotations.
- **Point-in-time queries.** `search()`, `Engine.search`, MCP `search_documents`, the HTTP search route and the CLI accept an optional `as_of` ISO date. When `as_of` falls before an edge's `effective_from`, the older text stays controlling and the newer text is `not_yet_in_force`. Without `as_of` the resolver uses the current date from an injected clock.
- **Evidence passthrough for Paper 2.** Answer evidence rows carry the three authority keys only when a search row has them, so answer output is unchanged when the stage is off.
- **Experiment 43 (authority resolution).** Synthetic corpus covering five case types (full supersession, general + specific, partial amendment, corroboration, unresolved conflict) plus amendment chains, then one real corpus (a UK statute with amending instruments from legislation.gov.uk). Five pre-registered metrics: stale authority rate, incorrect supersession rate, scope resolution accuracy, conflict detection recall, historical authority accuracy. Cells: baseline, newest-document-wins heuristic, deterministic tier only, model tier added (the candidates chosen in task 9.1), and resolver without the reconciliation step. A separate comparison of relation-typing models (the chosen candidates plus a small local LLM). The labelled evidence set is exported for Paper 2.
- **Web workspace.** The Knowledge Base search gains an optional "As of" date field, and result rows show an authority status badge with its reason. Rows without authority keys look as they do today. This group runs after Experiment 43.
- **ADR-090** recording the decision after the experiment reports.
- **Docs**: `docs/guides/configuration.md`, `docs/guides/mcp-tools.md`, `docs/guides/architecture.md`, `.env.example`, and the research proposal `docs/proposals/authority-aware-retrieval.md` (already drafted alongside this change).

No breaking changes. Everything is additive and off by default.

## Capabilities

### New Capabilities

- `authority-resolution`: typed, evidence-bearing relations between indexed sources; post-ingest extraction that does not depend on ingestion order; a query-time resolver that annotates candidates with exactly defined statuses without dropping them, honours `as_of`, and reports unresolved conflicts per row; a graph operation for user profiles; opt-in per profile; disabled path unchanged.

### Modified Capabilities

- `mcp-search-filtering`: `search_documents` gains an optional `as_of` parameter and, when the authority stage runs, per-row `authority_status`, `authority_reason` and `authority_conflicts`. The response stays a list of rows.
- `profiles-dual-use-case`: the profile bundle gains an `authority` section (`enabled`, `model_tier`) overlaid onto `EffectiveSettings.authority`; `documents` may enable it, `codebase` keeps it off.
- `strategy-registration-governance`: the `"authority"` strategy is registered through `core/retrieval/registry.py` and the `authority.resolve` operation through the retrieval graph adapters; both are dispatched without name branching.
- `experiment-validity-gates`: Experiment 43 pre-registers the five authority metrics, their exact definitions and the comparator cells before any default flip.
- `grounded-answer-synthesis`: evidence rows pass the authority keys through when present and stay unchanged when absent.
